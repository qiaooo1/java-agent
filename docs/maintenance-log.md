## 2026-11-19：修正请求方法与内容类型错误的 HTTP 响应

### 问题与改进

平台 `ApiErrors` 的通用异常处理会接住 Spring MVC 的请求方法、媒体类型异常，将应返回 405 或 415 的客户端错误转换为 500。调用方无法正确区分请求使用错误与服务故障，框架提供的协议响应头也被丢失。

新增两类专门的异常映射，复用异常中的状态码和响应头：不支持的方法返回 405 并保留 `Allow`；不支持的请求体类型返回 415 并保留 `Accept`。响应体继续使用统一的 `message` 字段，内部未知异常仍由原有兜底处理。

在 `PlatformApiTest` 中新增两个经过真实认证链的回归场景，检查状态、响应头、统一错误消息及不支持的请求体不会预留任务额度。API 文档同步补充两类错误的使用说明。

### 验证

- 修复前，平台 API 的八个测试中仅新增两项失败：分别期望 405、415，实际均为 500；其余六项通过。日志：`target/daily-api-protocol-before.log`。
- 修复后，运行 `mvn -o -B -ntp -pl platform-service -am test -Dtest=PlatformApiTest -Dsurefire.failIfNoSpecifiedTests=false`，八个测试全部通过，失败、错误、跳过均为 0。日志：`target/daily-api-protocol-after.log`。
- 首次运行受到宿主临时目录写入限制，后续仅在验证进程中将 `TEMP`、`TMP` 和 `java.io.tmpdir` 指向项目忽略目录 `target/java-tmp`，未修改项目的 Maven 配置。
- `git diff --check`：通过。本次仅执行平台 API 定向回归，未重跑其他模块测试、Docker 集成测试或 GitHub 云端检查。

### 设计说明

全局异常处理需要区分客户端协议错误、业务错误与未知服务异常。保留正确状态之外，还应保留 `Allow`、`Accept` 等响应头；支持的方法和媒体类型直接复用 Spring 的解析结果，避免手写重复清单与实际接口漂移。

## 2026-11-20：收到线程中断后及时停止 Outbox 发布批次

### 问题与改进

`DispatchPublisher.publish()` 在等待 RabbitMQ 确认时捕获 `InterruptedException`，虽然恢复了线程中断标记，但外层批次没有检查标记，仍会继续领取、发送后续候选消息。进入方法前已被中断的线程也会开始扫描待发记录，增加停机期间的无效工作与未确认消息。

在发布入口和每条候选消息领取前使用 `isInterrupted()` 检查停止信号，及时结束本批且不清除标记。已开始的消息沿用失败记录与重试处理，未领取的消息留待后续发布运行。普通 broker NACK 不等同于线程中断，仍允许继续处理其他候选。

新增发布前中断、确认等待期间中断、普通拒绝后继续发布三个回归场景。测试在调用线程中确定性设置中断、控制确认 future，不依赖休眠、外部 broker 或竞争时序；通过 finally 清理测试线程的中断状态。运维文档同步说明批次停止与至少一次投递的边界。

### 验证

- 修复前运行五个发布器测试，新增的发布前中断、确认等待中断两项失败；其余三项通过。分别观察到中断后仍扫描、仍领取第二条消息。日志：`target/daily-publisher-interrupt-before.log`。
- 修复后运行 `mvn -o -B -ntp -pl backend-common -am test -Dtest=DispatchPublisherTest -Dsurefire.failIfNoSpecifiedTests=false`，五个测试全部通过，失败、错误、跳过均为 0。日志：`target/daily-publisher-interrupt-after.log`。
- 测试进程的 `TEMP`、`TMP` 和 `java.io.tmpdir` 指向项目忽略目录 `target/java-tmp`，未修改 Maven 配置。
- `git diff --check`：通过。本次执行发布器定向单元回归，未重跑全量测试、真实 RabbitMQ 集成测试、实际进程停机验收或 GitHub 云端检查。

### 设计说明

Java 线程中断是协作式停止信号。捕获 `InterruptedException` 后恢复标记，还需要让外层控制流停止接收新工作；检查时使用不清除标记的 `isInterrupted()`。确认等待中断不表示 broker 未收到消息，因此重试仍依赖任务领取和结算幂等，不能宣称撤回消息或恰好一次投递。

## 2026-11-20：改造 IncidentHarness 统一运行层

## 2026-11-21：工具错误分类与安全有界恢复

### 问题与改进

原工具执行把所有失败压成字符串，引擎通过“错误”前缀判断成功，既可能误判正常业务文字，也无法可靠区分参数错误、授权拒绝、传输故障和不确定的超时。部分错误还会直接回传异常消息或 JSON 片段。

新增 `ToolResult`、`ToolErrorCode` 和受控 `ToolExecutionException`。注册表解包异步与反射异常后按类型分类；失败 Observation 只包含安全错误码、常量摘要与恢复建议，不携带原始参数、异常消息、堆栈或远端错误正文。原字符串接口保留兼容，ReAct 改为按结构化状态判断成功。

`@Tool.retrySafe` 默认关闭。Harness 仅对显式声明安全的工具，在瞬时故障时自动重试一次；每次真实尝试都消耗原有调用预算，最多一百毫秒的短退避同样计入原截止时间。重试不重发模型请求，退避前后与每次调用均检查取消和执行约束。参数与未知工具错误交给后续模型决策纠正，权限拒绝、资源不足、超时和硬性预算错误立即停止。未声明安全的工具发生传输故障时停止，避免无法确认外部副作用的重放。

诊断四类固定来源的只读工具明确开启安全恢复，HTTP 502/503/504 和传输故障提供瞬时分类；401/403、429、重定向、读取超时、无效数据及结果超限不自动重试。Worker 将安全尝试状态与重试安排记录为 `tool_attempt`、`tool_retry`，带调用标识、尝试编号、分类和等待时间，沿用原有 fencing 与所有者隔离。

## 2026-11-21：高并发下的任务调度与资源控制

### 问题与改进

容量不足时原来统一两秒后再次调度，持续饱和下容易集中竞争。Redis 释放只按 token 删除全局成员，没有同时核对用户侧归属；容量等待也缺少独立计数及可回放原因。

- 区分 `USER_LIMIT` / `PROVIDER_LIMIT`，原子 Lua 申请保留双重容量上限，非正数配置及不确定结果拒绝执行。释放必须同时匹配用户和 token，失效槽位仍不能续约复活。
- 容量等待采用带半窗随机抖动的指数退避，首次 1–2 秒，最高 15–30 秒。新增 V3 `capacity_deferrals`，不消耗执行尝试编号；实际领取时清零。等待状态、`capacity_wait` 事件和定时 Outbox 在同一事务中提交，同一等待窗口重复通知不再创建调度。
- 未到执行时间的旧通知直接确认，不访问 Redis 或初始化执行资源；申请响应不确定时拒绝领取、尝试清理本次 token 并退避重投。等待事务失败不得 ACK。初始化工具和心跳失败也进入客户端、工具资源清理流程。
- 分开暴露每实例消费者、单用户和全局容量配置；Compose 显式传递这些参数以及用户在途上限。消费者保持固定上限与 prefetch=1。旧并发属性作为回退保留。
- 前端识别容量等待事件，不生成假步骤，也不把重复容量等待计入已结束尝试的执行耗时。补充 API、调度设计、README、测试指南和本地 Redis 验证入口。

## 2026-11-21：工作记忆召回与执行状态管理

### 问题与改进

消息窗口虽已保护当前问题和最新工具组，但被裁剪的旧工具观察没有可召回入口。仅重读源工具既增加调用，也可能获得不同时间的状态；内存中的执行事实也缺少独立版本与权限保护的持久化记录。

- Harness 为每次执行创建独立 `WorkingMemory`，保存完成的业务工具观察并生成 `M1` 等引用索引。模型可通过 `recall_memory` 读取被裁剪的原始观察，无需重新调用源工具或扫描全部任务事件。它仍受相同预算、取消和截止时间约束，不访问其他用户或任务；召回本身不生成重复事实。
- 索引只含服务端引用、规范工具名和状态/容量元数据，计入上下文字符预算；原始观察仅作为 tool 数据返回。原问题及最新完整工具组仍受保护。首轮回归发现额外索引消息会使原有四消息窗口超限，改为合并纯控制元数据，保持四消息场景和总字符预算。
- 观察库默认上限为 64 条、总结果 64000 字符、单条完整结果 16000 字符；显式标记超大结果不可用和旧条目淘汰，不以截断片段冒充完整证据。快照可序列化并严格校验重建；损坏内容不覆盖已知状态。消息工具调用列表进行防御性复制。
- Flyway V4 新增 `task_memory`，按任务与执行尝试保存版本、迭代、观察序号和快照。保存与元数据审计事件在同一事务中，沿用租约/Worker/attempt fencing；重复保存幂等，旧序号和改写被拒绝，取消或失权后不能写入。
- 新增所有者保护的 `/api/tasks/{id}/memory` 与历史 `attempt` 查询，只返回索引及版本，不返回原始正文。旧任务没有快照时如实显示未初始化，新尝试不自动使用旧记忆。Worker 进度和审计能识别受控召回工具。
- README、API、Harness、安全与测试说明同步更新，并新增 `docs/10-working-memory-and-state.md`。
